# Companion protocol v1 (owned, not a Wisp API)

SDKs pinned at iroh-ffi / @number0/iroh 1.1.0. ALPN UTF-8 `wisp-remote/1`. iroh authenticates the remote endpoint public key and supplies QUIC encryption. Canonical application endpoint IDs are lowercase hex of the 32 public-key bytes, not SDK display strings.

One client-initiated bidirectional stream per operation. Client writes UTF-8 JSON then finishes its send half. Limit 64 KiB per request (attachment chunks 16 KiB decoded). Server replies with uint32 big-endian length followed by UTF-8 JSON; each response frame <= 8 MiB. Ordinary operation sends one frame then finishes; events sends many. Invalid event requests receive an error and terminate; accepted event streams are reset on exit. There are at most eight connections globally and two per authenticated endpoint key, allowing reconnect overlap without one peer consuming the pool. Protocol/version and exact envelope fields validated, connection/stream/time/queue limits enforced. No compression, arbitrary HTTP proxy, URLs, headers, filesystem paths or runtime credential.

Requests:
```
{v:1, op:"pair", token:"base64url 32 random bytes", name:"iPhone"}
{v:1, op:"pair.status", pendingId:"UUID"}
{v:1, op:"request", method:"GET|POST|PATCH", path:"/bridge/finite-route", body?:object}
{v:1, op:"events", sessionId:"UUID"}
{v:1, op:"app.state", ready:true|false}
```
Responses: `{ok:true,status:200|201|202,body:...}` or `{ok:false,status:number,error:{code,message}}`. Pair success body `{pendingId,state:"pending"}`; polling returns `{state:"pending|approved|rejected"}`. Authorization is checked from the authenticated connection identity on every request, never from client JSON.
Events: the server installs its event listener first, then sends `{ok:true,status:200,body:{subscribed:true}}` before starting the potentially slow snapshot query. The next frame is `{event:"snapshot",data:...}`, followed by state events buffered while that snapshot was built, then live `{event:"run|complete|connection|failure|ping",data:...}` frames. Client closes stream to unsubscribe. Disconnecting does not cancel Wisp run. Revocation closes all connections and event streams for that peer.

`app.state` is a private, authorized presence signal and accepts exactly one boolean. `true` leases foreground UI readiness for 15 seconds on that authenticated QUIC connection; the visible phone renews it every five seconds. `false` clears the lease. A new connection starts unready, and disconnect, background, unload, bootstrap/stream failure, or lease expiry removes readiness. The phone sends `false` only over an existing connection, so hiding the UI cannot trigger a dial. A companion that does not support this additive operation may reject it without breaking chat behavior.

QR URL: `wispremote://pair?data=<base64url UTF-8 JSON>` where JSON is `{v:1,endpointId:<hex>,ticket:<iroh endpoint ticket>,token:<random invitation>,expiresAt:<unix-ms>}`. Phone validates ticket's public key matches endpointId. Invitation expires after 120 seconds, consumed on first valid pairing request, and cannot authorize an RPC. Mac shows requesting phone fingerprint/name and explicitly approves. Pending approval expires after 120 seconds. Mac stores approved phone public keys; phone stores Mac endpoint identity/ticket. Endpoint private keys reside in Keychain, no cloud sync. Local control invitation is only delivered over child-process pipes to menu UI, never logged.

Native web client loads only bundled resources and has no remote navigation in the privileged WebView. JS uses `window.webkit.messageHandlers.wisp.postMessage({kind:"request",method,path,body})` (reply-capable handler) and receives the response envelope above. `{kind:"subscribe",sessionId,subscription:<UUID>}` replies `{ok:true,...}` and delivers CustomEvent `wisp-remote-event` detail `{subscription,event,data}`. Each native subscription attempt emits connection `{state:"connecting"}` before retry, then accepts only a fresh snapshot as its first stream frame and emits `{state:"connected"}` immediately after delivering that snapshot. `{kind:"unsubscribe",subscription}` cancels only that subscription. The finite `{kind:"appState",ready:boolean}` message updates the readiness lease; compatibility rejection is ignored safely. The exact local-only `{kind:"appearance",theme:"dark"|"light"}` message applies the matching iOS color scheme to the connected surface so system status text follows the web theme; it changes no system setting. On foreground resume native dispatches `wisp-remote-resume` with detail `{transport:"connected"|"connecting"}` so JS can refresh without discarding its current DOM or draft. Native replies with safe structured errors; arbitrary remote error strings are not shown. File picker remains in bundled UI; native `kind:"pickFiles"` support may supply prepared files (PDF text / JPEG / UTF-8), with same backend limits.

Transient route loss and backgrounding retain the WebView and its in-memory draft. The explicit native Disconnect action is a stronger boundary: it removes the connected surface, cancels subscriptions and every in-flight script-message operation, unregisters the message handler, stops loading, and closes the main transport so no pending web request can redial or retain readiness. A later explicit Reconnect creates a new WebView from bundled resources while preserving the saved pairing. Because Disconnect intentionally destroys the web surface, an unsent in-memory draft is not retained across that user action.

The exact local `copyText` operation accepts only `kind` and a UTF-8 string of at most 1 MiB, writes the general pasteboard after a user Copy click, and returns only `copied:true`. A public WKWebView subclass overrides `inputAccessoryView` with nil to omit the redundant form toolbar; CSS still owns the keyboard viewport. Transport failures during `POST /bridge/sessions`, like message submission, return `delivery_unknown` so first-send chat creation is never replayed silently. The native request allowlist includes only exact GET `/bridge/privacy` and POST `/bridge/privacy/refresh` for the normalized attestation surface.

The native allowlist additionally permits GET `/bridge/usage`, GET/POST `/bridge/sandbox`, and exact POST `/bridge/projects/<UUID>/remove`. Usage is a finite display-only projection; it exposes no payment or permission details. Sandbox accepts exactly one boolean field, enabled or allowNetwork, on the existing authenticated path, preserves the other field and approval policy, and rejects network changes while isolation is off. Project removal accepts only the exact bounded confirmation snapshot from the phone contract and returns only confirmed removed session IDs plus `complete`; neither the transport nor UI replays it. Transport failures return `sandbox_write_unknown` for Sandbox and `project_removal_unknown` for removal, requiring refresh and a new confirmation. Native WebViews honor the fixed scale-1 viewport and disable their public pinch recognizer.

Original Wisp availability is a separate Mac-local display check through NSWorkspace. When Wisp is closed, red eyes and “Wisp is closed” override the connectivity artwork without changing pairing or transport state.

Phone paired endpoint and private key are stored by native code, not JS/browser storage. Pairing requires native camera/paste UI before chat. Public-relay metadata and availability limitations are shown in setup, without claiming confidential production certification.

Official evidence checked 2026-10-16: https://docs.iroh.computer/languages/javascript ; https://docs.iroh.computer/languages/swift ; https://docs.iroh.computer/iroh-services/relays/public ; installed npm type definitions. No services/metrics client is enabled.

## Local Mac menu consumer

The existing private stdio status packet is `{type:"status",endpointId,peers,pending,pairingOpen,connections:[{peerId,route,ready}]}`. `peers` is remembered trust; only `connections` reflects established trusted QUIC transports. `ready` is true only while that exact connection has a fresh `app.state` lease; a missing field is false for compatibility. A `connecting` route means path selection is unknown after the handshake, not an unpaired device. Deduplicate peer IDs for counts. Status may precede process `ready`, is emitted on lifecycle changes and every three seconds. The Mac consumer timestamps receipt and considers snapshots older than ten seconds disconnected; child exit/error never leaves a green icon. This is private application presence, not a new Runtime permission or authorization rule.

The local popover and native auxiliary window load only bundled files under `wisp-menu://app/`. A finite native message handler accepts ready/resize/show-pairing/show-devices/invite/retry/close/quit/open-wisp/download-wisp and approve/reject/revoke with IDs checked against current pending/trusted state. Open resolves only the installed `com.sergeykolesnikov.wisp-desktop` bundle; download opens only the fixed `https://usewisp.io/` official page. Only an owned main frame can send commands; web navigation and web-created windows are denied. Native show-pairing/show-devices select constant surfaces in one auxiliary NSWindow. Resize/close target the WKWebView that sent the message; no caller-supplied URL, filename, or window identifier is accepted. State pushed to the view contains display-only peer data, public fingerprints and an in-memory QR PNG, never a private key or Runtime credential. Text is rendered without HTML interpretation. Invitations and approval expiration remain enforced by the existing pairing backend.

Synthetic states exist only in a separate `MENU_PREVIEW` developer build with its own bundle identifier. The installed build rejects `--preview` before creating the application or accessing Keychain.

Pairing UI uses only a fresh valid pending request. Yellow blinking eyes indicate a current invitation or pending approval, or a trusted phone transport whose UI has not yet completed bootstrap plus its first selected-session snapshot/subscription (or verified that there are no sessions). Reduce Motion keeps yellow steady. Green requires at least one trusted transport with a fresh explicit foreground readiness lease, even if its route is still being determined or a second phone is being paired. Black means no live trusted transport. The icon reports aggregate connectivity. Readiness lease expiry, background, disconnect, stale status and child errors cannot leave a green indicator.
