# Phone bridge contract (owned by this project)

These are our normalized routes, not claims about native Wisp API schemas. All routes require the existing owner/device gate. On the legacy HTTP hop, every request additionally requires a fresh per-launch capability shared privately between the in-process Tailscale adapter and loopback bridge; it is never sent to the phone. Direct standalone HTTP startup is disabled. No raw Runtime proxy. API uses JSON; errors `{error:{code,message}}` without internal logs or credentials.

`GET /bridge/bootstrap` → `{connection:{state,runtimeVersion},sessions:Session[],projects:Project[],models:Choice[],modes:Choice[],preferences:{modelId,mode,thinking},capabilities:{models,modes,thinking,projects,projectRemoval,approvals,attachments,connectors},selectedSessionId?}`.

Slow-changing model and billing-derived model-availability metadata is cached in Mac process memory for about 60 seconds and concurrent loads are coalesced. Every bootstrap and `GET /bridge/sandbox` performs a fresh sandbox read. Sessions and active runs are refreshed independently. The cache contains no chat history or approvals. Billing-derived model availability is only a UI hint; Wisp Runtime remains authoritative and enforces entitlement on every operation, including when cached metadata is present.

`GET /bridge/profile` → `{displayName?:string,avatarDataUrl?:string}`. This optional route is loaded independently so profile latency cannot delay bootstrap. The display name is bounded and control-character-free. The optional avatar is an inline base64 PNG, JPEG, or WebP whose decoded bytes are at most 256 KiB and whose file magic matches its declared media type. External URLs, SVG, email, subject, tokens, and all other profile fields stay on the Mac. The sanitized profile is cached in Mac process memory for about 60 seconds and failures are not cached.

`GET /bridge/sandbox` → `{enabled:boolean,allowNetwork:boolean}` from a fresh native read. `POST /bridge/sandbox` accepts exactly one boolean field, either `{enabled:boolean}` or `{allowNetwork:boolean}`, and returns the same full, freshly verified state. Empty bodies, both fields, unknown fields and non-booleans are rejected at every ingress and by the bridge itself. Sandbox writes are globally serialized. Each write first reads current state, sends only the selected partial native field, then performs an authoritative read-back and verifies both the selected value and preservation of the other field. An `allowNetwork` write is rejected while Sandbox is disabled. A failed or unverifiable native write returns a safe explicit error and is never automatically replayed.

`GET /bridge/usage` → `{available:boolean,planName?:string,usage?:{cycle?,daily?,weekly?}}` from native `/api/billing/me`. `planName` is bounded plain text. Each present usage window is `{percentUsed,resetsAt?}` with a finite percentage and optional valid timestamp. The read is lazy and coalesces only concurrent callers. Unavailable or malformed native data returns `{available:false}` without native errors or arbitrary fields. Subscription, payment, card, charge, invoice, permission and other settings fields are never returned. No `/bridge/account`, `/bridge/payments`, or permissions projection exists; Settings tabs other than Usage and Sandbox are informational Mac-only views and issue no requests.

`GET /bridge/privacy` → `Privacy`. `POST /bridge/privacy/refresh` with the exact empty body `{}` refreshes Wisp's existing attestation and returns the same normalized shape. These routes expose display data only; they do not alter attestation, sandbox enforcement, permissions, or privacy policy.

`Privacy` is `{status,measurements,failedChecks,keyProvider?,tcbStatus?,quoteFingerprint?,verifiedAt?}`. `status` is exactly one of `verified|failed|unreachable|unavailable|pending`. `measurements` is an object whose only possible keys are `appId|composeHash|imageDigest|mrtd`; each present value is `{value:string,match:boolean}`. `failedChecks` contains only `measurement_mismatch|nonce_freshness|signer_binding|tcb_status|quote_signature`. Optional strings and measurement values are bounded, control-character-free plain text. The bridge never returns native reasons, errors, expected measurements, configuration, credentials, tokens, or arbitrary upstream fields.

The bridge maps a native `failed` result whose reason starts with `attestation_unreachable` to `unreachable`. A native `verified` result requires native `measurements` and `expected` objects with at least one usable known measurement pair. An explicit mismatch, `false` nonce freshness or signer binding, non-up-to-date TCB status, or signature failure reports `failed`; absent optional check fields do not invent failures. Unknown, malformed, missing-proof, or unsupported verified results return the exact safe fallback `{status:"unavailable",measurements:{},failedChecks:[]}`. Remote transport encryption remains a separate fact and is not attestation evidence.

`GET /bridge/sessions/:id/connectors` → `{connectors:Connector[],available:boolean}`. Connector is `{id,label,status,enabled}`, where status is one of `connected|disconnected|connecting|failed|requires_auth`. The list contains only configured connectors and returns no URLs, credentials, raw configuration, counts, provider/auth identifiers or native errors. An unavailable connector API returns `{connectors:[],available:false}`.

`POST /bridge/sessions/:id/connectors` body `{id:string,enabled:boolean}` → the same normalized list after the mutation. The addressable connector ID must satisfy the finite public ID format and be present in the freshly fetched configured catalog. Enabling additionally requires current `connected` status; an already-enabled connector can still be disabled after its status changes. Mutations are serialized per session, each mutation reads and validates the latest bounded enabled list before its PUT, and every unrelated upstream enabled string is preserved even when it is not a public addressable ID. A malformed or unbounded native enabled list fails safely without a PUT. Add/remove, OAuth, global connection settings and connector configuration are outside this contract.

Session: `{id,title,projectId,updatedAt,active,hasArtifacts:boolean}`. `hasArtifacts` is the boolean presence of native `deskPath`; the path itself is never returned. Project: `{id,name,path}`. Choice: `{id,label,description?}`. IDs are opaque. Render only returned choices; no hardcoded model inventory.

Desktop parity correction (2026-10-16): the native picked-project registry is the sole source of project membership; old companion `state.roots` must not add projects. The global `/v1/sessions?origin=desktop` response is the sole source of session membership, including sessions whose project root is unavailable; known roots enrich access hints without filtering the global set. Do not substitute a working directory for an unknown project. A new project must be registered with Desktop before creating its Runtime session or returning success; failed registration returns a safe `desktop_registration_failed` error and preserves existing data. This persistence contract does not imply that an already-open original Desktop window automatically refreshes.

`GET /bridge/sessions/:id` → `{session:Session,messages:Message[],run:Run|null,settings:{modelId?,mode?,thinking?}}`.
Message: `{id,role,text,activities?:Activity[],thinking?:string}`.
Activity: `{id,type,title,status,detail?,text?}`; plain text only. Run: `{id,state,text?,activities:Activity[],confirmation?:{id,title,description},error?}`.

`POST /bridge/sessions` body `{projectId?:string,title?:string}` → `{session}`; native origin must be desktop. Omitted `projectId` creates a normal projectless chat: omit native `projectRoot`, create no project directory/registry entry, and add no technical prefix. The global New Chat button always uses this form, including while a project chat is open. Only an explicit project picker or that project's New Chat action supplies `projectId`.
`PATCH /bridge/sessions/:id` body `{title}` → `{session}`.
`POST /bridge/projects` body `{name}` → `{project}`; creates a named directory only below our managed project root.

`POST /bridge/projects/:id/remove` accepts exactly `{sessionIds:UUID[],activeSessionId:UUID|null}` and returns `{removedSessionIds:UUID[],complete:boolean}`. Both fields are required; the list is limited to 750 IDs so the full request fits every transport limit. Unknown fields, duplicate or malformed IDs, and a non-member active ID are rejected. Before any write, the bridge serializes project removals, loads a fresh global Desktop session snapshot and requires `sessionIds` to equal that project's complete member set. A missing registry entry is allowed only for a nonempty matching Desktop session group; its trusted root hint is omitted. A missing group returns `project_missing`; a changed, incomplete or out-of-project snapshot returns `project_snapshot_changed`; malformed or unverifiable native membership returns `project_removal_unavailable`. The client must refresh and ask for a new confirmation after any rejection.

For a validated removal, the bridge processes sessions sequentially with `activeSessionId` last. Each session is cancelled best-effort and then deleted through Wisp's existing session route with the trusted registered project-root hint. Delete `409` is retried after 200, 400, 800 and 1600 ms; `404` is accepted as already absent. Any other or exhausted outcome stops the sequence and is never automatically replayed. The bridge then reloads authoritative membership. `removedSessionIds` contains only requested IDs confirmed absent; `complete` is true only when that project has no remaining sessions. A partial result is a normal 200 response with `complete:false`; the client refreshes and requires a new destructive confirmation before another request. Transport loss is `project_removal_unknown` and is handled the same way. This operation never edits the picked-project registry, project folders, or other filesystem state; the project remains a composer picker choice.

`POST /bridge/sessions/:id/remove` accepts exactly `{}` and returns `{removedSessionId:UUID}` only after a fresh global Desktop session snapshot confirms absence. Bootstrap capability `sessionRemoval:true` gates this additive route. The command validates fresh Desktop membership before mutation, uses a trusted registered project hint when present, and omits it for a matching pathless Desktop session; it shares serialization with project removal, and uses original Wisp's best-effort cancel then DELETE with bounded 409 retries. Unknown failures never replay; the client refreshes before offering a new user action. No folders, registry, unrelated chats, or pin preferences are edited.

Original Wisp 0.2.7 pin source is its WebView `localStorage` key `wisp:starredSessions`, updated solely by its UI store; the Runtime has no verified pin projection or command. Remote must not invent a phone-only pin store or claim shared pin state. By explicit user preference, Pin is hidden until a supported native bridge exists.

`POST /bridge/sessions/:id/messages` body `{id,text,modelId?,mode?,thinking?}` →202 `{accepted:true,runId?}`. Client UUID is an idempotency key; never automatically replay on unknown outcome. One active turn per session; backend continues when browser disconnects.
`POST /bridge/sessions/:id/cancel` body `{}` → `{ok:true}`.
`POST /bridge/sessions/:id/confirmations/:confirmationId` body `{decision:'approve_once'|'deny'}` → `{ok:true}`; only real pending confirmation of that session/run.

`GET /bridge/events?sessionId=<id>` uses EventSource SSE. Events: `snapshot` with full session view, `run` with Run, `complete` with full session view, `connection` with connection state, `failure` with safe error, and `ping` with `{}` at about 15-second intervals. The initial `snapshot` is loaded before the stream is accepted; snapshot failure returns a normal safe HTTP error instead of a live-looking stream. Renderer supports streamed text, expandable activities and actual pending approvals. On reconnect fetch full view; do not erase messages on a network failure. While viewing, refresh bootstrap/session on focus and periodically (5s idle) to pick up Desktop changes. Backend owns upstream SSE and may attach to active Desktop run.

Static files: `/`, `/mobile.js`, `/mobile.css`, `/account-settings.js`, `/account-settings.css`; no third-party assets or browser storage. Avatar images use only a local Blob URL made from the normalized inline raster bytes, so CSP permits `blob:` for images without permitting `data:` or external image hosts. New UI will use these separate files while original proof remains rollback.


Implemented refinements: Run states include `running`, `queued`, `awaiting_approval`, `cancelling`, `cancelled`, `complete`, `unknown`, `error`; optional `thinking` is user-visible text if native provides it. Choice may include `disabled/disabledReason`. Bootstrap includes read-only `sandbox:{enabled,allowNetwork}`. Project create also returns its first `{session}`, and project metadata reports `desktopRegistered`. Errors with code `delivery_unknown` preserve client UUID; a same-ID check queries native status without dispatch. Only a confirmed native result may return accepted; unresolved delivery stays explicit. Full native history preserves tool error status.


## Device-local interface controls

The embedded iPhone page may send exactly `{ "kind": "connectionSettings" }` to its native message handler. The trusted main-frame origin check remains mandatory. The message only opens the native connection sheet and returns `{ "ok": true, "status": 200, "body": { "presented": true } }`; it does not authorize, disconnect, forget, or forward a request to the Mac. The user chooses those actions in the native sheet, with a separate Forget confirmation.

Appearance is a device-local light/dark toggle available only in the header; an earlier saved System preference is still understood for compatibility. No chat text, attachment data, model response or Runtime credential is stored in browser persistent storage. Drafts and uncertain-delivery identifiers are held per chat in memory, preserved across navigation and transient connection state changes, and cleared when the web view closes. Deliberate Sandbox enabled and allowNetwork changes are the only global-setting writes in this contract; approval settings remain outside it.

New Chat opens an in-memory draft without a create request. First send serializes session creation, any locally prepared attachment uploads, and the existing idempotent message submission. Draft attachments retain the 10-file, 5 MiB/file, 15 MiB total limits and are uploaded only after the user sends. A lost create acknowledgement blocks automatic repeat creation and tells the user to check the chat list. Ordinary background connectivity errors appear in the header; uncertain delivery and actionable mutation errors remain explicit.

User-initiated icon Copy sends exactly `{kind:"copyText",text:string}` to the native main-frame bridge (UTF-8 at most 1,048,576 bytes), which writes the general pasteboard and returns `{ok:true,status:200,body:{copied:true}}`. Browser preview uses the Clipboard API. No clipboard read or automatic copy occurs. The native picker accepts the local draft UUID as its selection correlation ID; this does not create a Runtime session or relax upload authorization.

On iPhone, a native `UIDropInteraction` loads file representations directly from `NSItemProvider`, bypassing WebKit File URLs (which can fail to read under the private URL scheme). Provider loads start during `performDrop`; temporary URLs are consumed within their completion callbacks. A serial queue prepares each file through the same PDFKit/ImageIO/UTF-8 pipeline as the picker, enforcing 25 MiB source size, 5 MiB prepared file, 15 MiB batch and 10-file limits. The app does not copy the provider files into persistent storage.

The bundled main frame reports exactly `{kind:"fileDropState",enabled:boolean,selectionId:UUID|null}` so iOS can offer Copy only for an available destination. At drop, iOS captures the destination and creates a private single-use batch ID. `window.wispImportDrop(id,selectionId)` checks the destination and locks the composer before requesting exactly `{kind:"takeDroppedFiles",id:UUID}`. The bridge accepts only that pending batch, returning `{ok:true,status:200,body:{files:[PreparedFile]}}` or a normalized attachment error. No paths, URLs or raw source bytes are accepted from JavaScript. Native loads are cancelled on teardown or after 60 seconds. Picker and drop preparation are mutually exclusive.

Drop acceptance uses the same connection, capability and busy-state gates as the attachment button. Native provider data never enters the textarea. Browser-preview file drags use `DataTransfer.files` captured synchronously during `drop`, preventing navigation/default text insertion. Preparation locks the composer and binds results to the selected chat/draft. A changed destination discards late results. Drops never send a message or create a chat; new-chat attachments remain in memory until Send. Browser preview retains text/image support and explains that PDFs require the iPhone app. Unavailable destinations and unsupported provider types reject the drop. Failed preparations show a recoverable attachment error.


## iPhone tactile feedback (2026-10-17)

The bundled main frame may send exactly `{kind:"haptic",event:"prepare"|"selection"|"light"|"context"|"success"|"warning"|"error"}` through the existing native bridge. It is a local UI command, never forwarded to the Mac/Runtime. Unknown events or extra fields are rejected. The acknowledgement `{ok:true,status:200,body:{accepted:true}}` confirms handling, not physical playback. The client tolerates unsupported older apps and browsers without blocking actions or showing errors.

UIKit supplies all patterns: selection feedback, light/medium impact (`light`/`context`) and success/warning/error notifications. `prepare` only prewarms the medium impact before a possible long press. Native handling respects active application state and a short rate limit; no custom duration/intensity/pattern is accepted. Haptics are always enabled within the app, with no switch or enable preference. Previously saved disabled values are ignored.

Feedback follows explicit user actions and real state changes. A completed long hold emits once when its menu opens; scrolling, cancelled holds and automatic rendering are silent. Destructive confirmations use warning; only confirmed completion uses success. Unknown/failed operations never emit success. Notifications are suppressed after navigation or backgrounding, and background refresh/stream tokens never generate feedback.
